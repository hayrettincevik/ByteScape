# Architecture

ByteScape is a C# / .NET 8 program for Windows 10 and 11 (x64). The user interface is WPF; everything that does not need a
window lives in a separate class library, so it can be tested and driven from the command line and the diagnostics harness.

## Projects

| Project | Contents |
|---|---|
| `ByteScape.Core` | The engine: scanning, the tree model, filters, the treemap layout, every analysis (caches, programs, games, developer leftovers, duplicates, forecasts), deleting, exports, snapshots, settings, localization. No UI dependency. |
| `ByteScape.Wpf` | The application (`ByteScape.exe`): main window with tabbed views, the map control, every dialog, theming, the first-start tour, the Explorer menu COM server. |
| `ByteScape.Tests` | xunit tests for the engine and every window (windows are rendered off screen). |
| `ByteScape.Diag` | A console harness for measurements, large synthetic trees, NTFS corner cases and the translation tools. Not part of the solution; build it on its own. |
| `store/` | Store package (MSIX) and portable build scripts, icons, the optional web site build. |
| `site/` | Pages of the optional download site. |

The product name, version, copyright holder and project addresses are defined in one place: `ByteScape.Core/Branding.cs`.

## ByteScape.Core

| Folder | What it does |
|---|---|
| `Core/Model` | The tree: `FsNode`, `FileNode`, `ContainerNode`, `DriveNode`. Paths are built once per node; trees are at most `FsNode.MaxDepth` (256) levels deep. |
| `Core/Scanning` | `DirectoryScanner` lists folders in parallel; `ScanJob` / `ScanTree` run the master scan and zoomed sub-scans and keep the tree live (file system watcher). `DriveProfile` picks a strategy per drive kind (HDD in disk order, SATA SSD, NVMe, USB, network). `Mft/` reads the NTFS master file table directly when the program runs as administrator. `ChangeJournal` uses the NTFS change journal for quick rescans (no administrator rights needed). `HardLinks` counts hard-linked files once. `ScanResume` keeps unfinished and finished scans to continue or refresh them later. |
| `Core/Filtering` | The filter language (`*.mp4;>100mb;<6months;:red`), wildcard matching, and `NaturalFilter`, which turns plain English or Turkish phrases into filters. |
| `Core/Knowledge` | Cache Radar: rules for known caches and temporary folders, with what deleting them does and how to clean them. |
| `Core/Cleanup` | Delete safety levels, access probes (in use, needs administrator), the delete guard against link swaps, Recycle Bin and permanent deletes, the cleanup lists. |
| `Core/Apps` | Installed programs (registry and Store packages) and the folders each one uses. |
| `Core/Games` | Steam, Epic Games and GOG libraries, play history and leftovers of removed games. |
| `Core/Dev` | Developer leftovers: rebuildable folders such as `node_modules`, `bin`/`obj`, `target`, `.venv`, per project. |
| `Core/Cloud` | OneDrive / Dropbox / iCloud placeholders: online-only files take no space, pinned and local copies do. |
| `Core/Compare` | Tree comparison with a snapshot, and folder comparison (optionally by content). |
| `Core/Duplicates` | Duplicate files by length, file id and SHA-256; one copy always stays. |
| `Core/Forecast` | Disk history (a small CSV and folder summaries next to the settings) and the disk-full forecast. |
| `Core/Export` | Text export templates and the CSV, JSON and HTML reports. |
| `Core/Snapshot` | Binary snapshots (`.sns`, see [snapshot-format.md](snapshot-format.md)) and `du` output. |
| `Core/Config` | Settings (XML). The file sits next to the portable exe when that folder is writable, otherwise in `%LOCALAPPDATA%\ByteScape` (always for the Store app). |
| `Core/Ai` | The optional local AI layer (an Ollama or OpenAI-compatible server the user runs); off by default. |
| `Core/Update` | The update check of the portable exe (GitHub releases, opt-in). |
| `Core/Localization` | `Loc` and the translation catalogs (see below). |
| `Core/Legal` | The licence and third-party notices shown in About. |
| `Core/Util` | Crash log, problem report, DPAPI secret storage, safe starting of Windows tools, CSV cells and other helpers. |
| `Treemap/Layout` | The squarified layout engine (`Squarify`, `StableSquarify`, `TreemapLayoutEngine`), independent of any renderer. |
| `Treemap/ViewModel` | View state of a map: zoom, selection, filter, highlights, comparison overlay. |
| `Interop` | Native Windows calls (shell menu, privileges, alternate data streams). |

### Treemap layout

The layout follows the squarified treemap algorithm (Bruls, Huizing and van Wijk), with the same formulation as
d3-hierarchy's squarify tiling; `SquarifyTests` compares the result with reference rectangles generated by d3
(`ByteScape.Tests/d3_reference.json`, made by `d3_reference_gen.mjs`) to 1e-6. The last item of a row and the last row
take the remaining space exactly, so floating point never leaves gaps or overlaps; NaN, infinite and negative values count
as zero. `StableSquarify` keeps a parent's row partition while the same children change size, so blocks do not jump around
during a scan. The "element proportions" setting scales the x axis around the engine instead of changing the algorithm.

### Scanning

A scan starts with the fastest method available: the MFT reader (local NTFS drive root, administrator), otherwise parallel
folder listing with a worker count that suits the drive. A finished scan records an NTFS change journal mark; the next
rescan — also after a restart — reads only the journal records since then and lists only the folders that changed. Scans
can be paused, stopped and resumed later; unfinished trees are saved when the program closes.

### Deleting

Every file and folder gets a safety verdict (safe, safe when the program is closed, unknown, caution, personal, protected).
Windows, program folders, profile roots and other system places are protected. Deleting goes to the Recycle Bin unless the
user chooses otherwise; while an item is deleted, every folder on its path is held open so that it cannot be swapped for a
link. Details: [security-review.md](security-review.md).

## ByteScape.Wpf

- `MainWindow` hosts tabbed views; `Views/ScanView` is one view (breadcrumb, filter box, map, details panel, status bar).
- `Controls/TreemapView` draws the map with `DrawingContext`, handles the keyboard and exposes the map to UI Automation
  (`Controls/TreemapAutomation`). See [accessibility.md](accessibility.md).
- `Windows/*` are the dialogs and tool windows (programs, games, developer leftovers, cleanup, duplicates, comparisons,
  forecast, history, settings, export, problem report, about, help).
- `Dialogs` routes every message box, modal window, file picker, process start and clipboard call, so tests can answer
  them without a real dialog.
- `Localizer` applies the translations to a window; `ThemeManager` applies the single light theme and Windows contrast
  themes; `Tour` is the first-start tour.
- `Shell/ExplorerCommand` is the COM class behind "Open in ByteScape" in Explorer's menu for the Store package; the
  portable exe adds a classic menu entry under `HKCU\Software\Classes` instead (`Core/ShellIntegration.cs`).

## Localization

The English text is the key. `T("...")`, `F($"...")` and `P(n, "one", "other")` look texts up by a 32-bit FNV-1a hash of
the English text in the catalogs `ByteScape.Core/Core/Localization/<code>.txt` (Turkish, Russian, Simplified Chinese,
French, Spanish, Brazilian Portuguese), with CLDR plural forms. XAML attributes are translated by `Localizer.Apply`. The
pseudo language `qps` wraps every text in ⟦⟧ to find untranslated ones. `LocalizationTests` fail when a text in the source
has no translation in a catalog, when a catalog has stale entries or when placeholders differ, and the UI tests check that
every window fits its texts in every language.

On purpose in English: logs, crash and problem reports, CSV/JSON output, the command line syntax and the prompts sent to
the local AI. The natural-language filter understands English and Turkish.

## Tests

`dotnet test ByteScape.Tests` runs everything (a few minutes). Highlights:

- Layout invariants and the d3 parity check; filter language, exports and snapshots; real scans of temporary folders.
- An in-memory NTFS image for the MFT parser; a private cloud sync root for placeholder tests; the change journal.
- Every window rendered off screen on an STA thread (`WpfHost`), in every language and the pseudo language.
- `EveryCommandTests` presses every button, menu item, list choice and toggle of every window (more than 2000 commands).
- `AccessibilityTests` audit the UI Automation tree, contrast and high contrast; `SecurityTests` cover the findings of
  the security review.
- Optional output for humans: `BYTESCAPE_LOC_SHOTS=1` and `BYTESCAPE_A11Y_SHOTS=1` save window screenshots under
  `%TEMP%\bytescape-tests`; `BYTESCAPE_STORE_SHOTS=<folder>` renders the Store screenshots from a made-up drive.

Tests never touch the user's files: they work in `%TEMP%`, redirect the settings, crash reports and resume folders, and the
one test that really uses the Recycle Bin removes its own item from it.

## Files the program writes

Next to the settings file (beside the portable exe, or in `%LOCALAPPDATA%\ByteScape`): `ByteScapeConfig.xml`,
`ByteScapeHistory.csv` and `ByteScapeHistory\` (disk forecast; can be turned off), `ByteScapeResume\` (unfinished and
recent scans; can be turned off) and crash reports. Nothing is sent anywhere; see [PRIVACY.md](../PRIVACY.md).
